## 二、模块清单与端口映射（✅ **含一处必须回报的冲突**）

### 2.1 实际端口分配

| # | 模块 | 类型 | 端口 | 状态 |
|---|---|---|---|---|
| 1 | `judge-common` | JAR 库 | **不占端口** | ✅ |
| 2 | `judge-api` | JAR 库 | **不占端口** | ✅ |
| 3 | `judge-gateway` | 可运行 | **9080** | ✅ P1 已起 |
| 4 | `judge-auth` | 可运行 | **9081** | ✅ P1 已起 |
| 5 | `judge-user` | 可运行 | **9082** | ✅ P1 已起 |

后续阶段续用 9083–9087（problem/submission/worker/contest/ai），判题机多实例 9085/9185/9285。基础设施见 `.env.example`：MySQL 3307、Redis 6380、PG 5433、namesrv 9877、broker 10919/10921/10922、Dashboard 18081、MinIO 9000/9001。

### 2.2 ⚠️ 与本次任务描述不符的两点（已按实况落地，请确认）

| 任务描述 | 实况 | 原因 |
|---|---|---|
| "服务端口调整为 **9080 与 9081**"（两个） | 实际需要 **9080 / 9081 / 9082**（三个） | 登录链路要求 `judge-auth` 经 Feign `UserClient` 查 `judge_user.user` 的 BCrypt 密码。**没有 `judge-user`，P1「能登录拿到双 Token」这条验收根本无法达成** —— 会让 P1 变成一个"能启动但登录不了"的半成品。故 P1 纳入 `judge-user`，占第 3 个端口。 |
| "复用 judge-common、judge-api、judge-gateway、judge-auth **四个模块**" | 实为 **五个模块**（多一个 `judge-user`） | 同上 |
| "**common** 作为公共依赖不占用端口" | ✅ 正确，且**`judge-api` 同样不占端口** | 二者 packaging 为 jar，仅被依赖，无 `server.port` |

> 若你确实要求"严格只起 2 个服务端口"，唯一可行替代是把 `judge-user` 的账号查询**合进 `judge-auth` 直连 `judge_user` 库**（跳过 Feign）。但那会破坏底座「auth 负责 RBAC、user 负责账号」的边界，且与 PLAN.md 的模块划分冲突 —— **不建议**，需你显式拍板。

## 五、公共底座代码清单（judge-common，50 个主类）

### 5.1 统一响应结构

| 类 | 职责 |
|---|---|
| `domain.R<T>` | 统一响应体：`code` / `msg` / `data` / `requestId`；`ok()` / `error()` 静态工厂；`success()` 判 200 |
| `advice.WrapperResponseBodyAdvice` | 自动把 Controller 返回值包成 `R<T>`。**跳过**：`@NoWrapper` 标注、返回类型已是 `R`、springdoc 文档路径；`String` 返回值手工序列化（否则 ClassCastException） |
| `annotation.NoWrapper` | 免包装标记 |
| `jackson.SafeLongSerializer` | 雪花 ID 的 Long → String，防前端 JS 精度丢失 |

### 5.2 全局异常处理

| 类 | 职责 |
|---|---|
| `exceptions.ErrorCode` | 错误码枚举：200/400/401/403/404/405/423/500/504 + 业务码 1001–1005 |
| `exceptions.CommonException` | 通用业务异常基类（**底座无 `BizException`**，勿新造） |
| `exceptions.` 其余 8 类 | `UnauthorizedException` / `ForbiddenException` / `BadRequestException` / `BizIllegalException` / `DbException` / `AccountDisabledException` / `RequestTimeoutException` |
| `advice.CommonExceptionAdvice` | 全局异常处理（Servlet + WebFlux 双栈）。含：参数校验 400、类型不匹配 400、`ResponseStatusException` 按原状态码映射、`DataIntegrityViolationException` → 400 可读提示、兜底 500 |
| `advice.ServletCommonExceptionAdvice` | Servlet 栈专属（404/405/缺参），`@Order(HIGHEST_PRECEDENCE)` 先于上面生效 |

> 双栈要点：`judge-common` 同时被 Servlet 服务与纯 WebFlux 服务（P5 的 `judge-ai`）依赖，引用 `jakarta.servlet`/`spring-webmvc` 的组件**必须加 Servlet 环境条件**，否则 WebFlux 类路径上 `NoClassDefFoundError` 启动失败。

## 六、各模块关键配置要点

### 6.1 三份 `application.yml` 的公共骨架

```yaml
server:
  port: 9080            # 9081 / 9082 对应 auth / user
spring:
  config:
    import:
      - optional:file:./.env[.properties]      # 单模块启动
      - optional:file:../.env[.properties]     # IDE 多模块 / 从模块目录启动
  application:
    name: judge-gateway
  threads:
    virtual:
      enabled: true     # 虚拟线程
```

**零硬编码**：数据源、Redis、JWT 密钥全部 `${VAR}` 占位，实值只在 `.env`（已 gitignore）。

### 6.2 各模块差异点

| 模块 | 差异 |
|---|---|
| `judge-gateway` | 无数据源；`spring.data.redis` 为 reactive；`globalcors.allowedOriginPatterns` **必须同时覆盖 localhost 与 127.0.0.1 且端口用 `[*]`**（否则"页面能开、一写操作就 403"）；`httpclient.response-timeout: 30s`，SSE 路由单独覆盖为 `900000`；**路由表已预置 P2–P5**（problem 9083 / submission 9084 / contest 9086 / ai 9087） |
| `judge-auth` | 数据源指向 `judge_auth`；`simple.instances.judge-user` 静态实例（关闭 Nacos 时供 Feign 解析）；`cj.admin-bootstrap.*` 首管理员引导配置 |
| `judge-user` | 数据源指向 `judge_user`；**无需**静态实例（无 Feign 出向调用） |

### 6.3 启动类

```java
// judge-gateway
@SpringBootApplication
@EnableScheduling
public class GatewayApplication {
    public static void main(String[] args) {
        new SpringApplicationBuilder(GatewayApplication.class).run(args);
    }
}

// judge-auth
@SpringBootApplication
@MapperScan("com.codejudge.auth.mapper")
@EnableFeignClients(basePackages = "com.codejudge.api.client")
public class AuthApplication { /* 同上形式 */ }

// judge-user
@SpringBootApplication
@MapperScan("com.codejudge.user.mapper")
public class UserApplication { /* 同上形式 */ }
```

> `@EnableFeignClients` 的扫描包是 **`com.codejudge.api.client`**（契约在 judge-api，不在本模块内）—— 这是包名改造后最容易漏的一处。
