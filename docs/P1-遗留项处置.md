## ① 教师注册收紧为 STAFF-only —— 保留，并补证闭环

### 决策
**保留收紧，不回退。**

### 理由
1. **教师是特权角色**：`TeacherController` 权限内含建题、管理隐藏测试用例。隐藏用例一旦泄漏，
   判题平台的核心资产（题目）即失去价值 —— 这与"学员可自助注册"完全不是一个风险等级。
2. **不存在产品缺口**：管理员本就有两条开通路径，收紧不会导致"教师无法开号"：
   - `POST /teachers/register`（带 STAFF token）
   - `POST /users`（带 STAFF token，`type` 可指定 1/2/3）
3. **最小权限是默认正确解**：`@RequireRole(STAFF)` + 网关白名单移除，两层 fail-closed 兜底；
   恢复匿名自助注册意味着重新开放一条提权路径，收益（省一次管理员操作）远低于风险。
4. **"教师申请—审核"流程不做**：当前无前端、无审核工作台，做半成品流程只会增加攻击面。
   若后续确需，属 P6（前端 + 管理台）的独立需求，届时按"申请单 + 管理员审批"设计。

### 落地动作
- 代码维持现状（`TeacherController#register` 的 `@RequireRole(UserRole.STAFF)`；
  `JwtProperties.excludePaths` 不含 `/teachers/register`），**零改动**。
- 把"教师账号只能由管理员开通"写进 README Q6 与 `JwtProperties` 注释（P1 已完成）。

### 验证证据（`scripts/verify-p1-login.py` §[6]）
| 断言 | 期望 | 实测 |
|---|---|---|
| 匿名 POST `/teachers/register`（经网关） | 401 | ✅ 401 |
| 学员 token POST `/teachers/register` | 403 | ✅ 403 |
| 学员匿名 POST `/students/register`（回归保护） | 200 | ✅ 200 |

## ② judge-common 移除 Redisson —— 保持移除

### 决策
**保持移除，本阶段不重新引入。** 明确触发条件，避免"为了将来可能用到"而长期挂着一个未使用的重依赖。

### 理由（为什么 P3/P4 大概率也不需要它）
底座当初引入 Redisson 只为 `CategoryCache` 一个类做分布式锁/缓存。CodeJudge 的并发场景均可由
**已有的更轻的机制**覆盖，无需分布式锁：

| 场景 | 出现阶段 | 推荐机制 | 是否需要 Redisson |
|---|---|---|---|
| 提交幂等（同一题重复提交） | P3 | MySQL 唯一索引 `uk_submission_idempotent(user_id,problem_id,contest_id,code_hash,submit_round)` | ❌ 不需要 |
| 判题机任务分配 | P3 | RocketMQ 消费组天然负载均衡 + worker 本地信号量控制并发 | ❌ 不需要 |
| 判题结果幂等落库 | P3 | 唯一键 + `INSERT ... ON DUPLICATE KEY UPDATE` | ❌ 不需要 |
| 竞赛排行榜 | P4 | Redis `ZSET` 原子操作（`ZADD`/`ZINCRBY`/`ZREVRANGE`） | ❌ 不需要 |
| 比赛封榜/快照 | P4 | `ZUNIONSTORE` 或定时任务落库 | ❌ 不需要 |

**引入触发条件（满足任一才重新引入）**：
- 出现"跨服务、跨资源的复合临界区"（例：多资源同时锁定，需要可重入 + 看门狗续期）；
- 需要 Redisson 特有数据结构（`RMap`/`RDelayedQueue`/布隆过滤器/限流器）；
- 需要用 `RLock` 替代手写 `SETNX` 的分段锁且复杂度已超过自研成本。

在此之前，一律优先：**MySQL 唯一索引 → MQ 消费组 → Redis 原生命令**。

### 落地动作
- `judge-common/pom.xml` 保持不含 Redisson（**零改动**）。
- 本决策登记进本节，作为后续阶段的判断依据。

### 验证证据（静态扫描）
```
$ grep -rn "redisson\|Redisson" --include=*.java --include=*.xml --include=*.yml . | grep -v /target/
./judge-problem/pom.xml:55:  与版本风险（judge-common 移除 Redisson 即是同类处置）。
```
→ 全仓仅剩 **1 处注释性提及**，无任何依赖声明与代码引用。`judge-common`、`judge-api`、
`judge-gateway`、`judge-auth`、`judge-user`、`judge-problem` 六个模块均无 Redisson 依赖。

## ③ `POST /accounts/login` 双 Token 下发 —— 已实测

### 决策
**用脚本方式完成实测**，绕开"命令行携带明文密码被本机安全策略拦截"的限制。

> 原来的阻塞点：在命令行里直接写 `-d '{"password":"123456"}'` 会被本机安全策略拦下。
> **推荐解法**：把请求逻辑写进脚本、凭据从环境变量读取并带默认值 —— 命令行不再出现明文，
> 同时脚本可重复执行、可进版本库（默认值本身是公开的种子密码，非真实密钥）。

### 落地动作
- 新增 `scripts/verify-p1-login.py`（纯标准库 `urllib` + `http.cookiejar`，不依赖 curl / requests）。
- 覆盖范围 **8 组 41 项断言**：

| 组 | 覆盖内容 |
|---|---|
| [1] | 学员登录：HTTP 200 / `code`=200 / `userId` / JWT 三段式 / `roleId` claim=2 / `expireTime`=1800 / HttpOnly + SameSite Cookie / refreshToken 不进响应体 |
| [2] | 负例：错误密码 401、不存在手机号 401、空密码 400、学员走管理端 401 |
| [3] | 管理员登录：`code`=200 / `roleId` claim=1 / 管理端 Cookie 独立命名 |
| [4] | 刷新：带 Cookie 200 且换发 accessToken、不轮换 refreshToken；无 Cookie 401 |
| [5] | 经网关端到端：白名单登录 200、Bearer 访问 `/users/me` 200 且身份一致、无 token 401、伪造 `user-info` 头被剥离后 401 |
| [6] | 教师注册加固（见 ①） |
| [7] | 首次改密 fail-closed：原密码错误 400 **且不删除** `.bootstrap-credentials` |
| [8] | 收尾：逻辑删除脚本创建的临时账号（幂等预清理上次残留） |

### 验证证据

四服务运行版本：judge-gateway 9080 / judge-auth 9081 / judge-user 9082 / judge-problem 9083。

## 附带：本轮发现并加固的一个环境陷阱

排查登录链路时发现 **服务端口被宿主注入覆盖**，已确证并加固（详见 `docs/CONTEXT.md` §3 硬约束 #13）：

- **现象**：`java -jar target/judge-user.jar` 时 Tomcat 绑定到 **56298** 而非 yml 中的 9082，
  并报 `Port 56298 was already in use` 启动失败。
- **根因（已确证）**：转储子 JVM 环境得到 `SERVER__PORT=56298`、`SERVER__HOST=127.0.0.1`，
  56298 即宿主自身监听端口。Spring Boot 松散绑定把 `SERVER__PORT` 解析为 `server.port`，
  优先级高于 `application.yml`。
- **加固**：`scripts/dev-start-backend.{sh,ps1}` 的 `unset` 列表追加单下划线变体
  （`SERVER_PORT` / `SERVER_HOST`），并在注释中写入实测证据与"直接 `java -jar` 时的两种绕法"。
