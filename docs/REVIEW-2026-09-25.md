## 二、高危问题（7 项，全部已修）

### S1. `/jwks` 匿名泄露 JWT HMAC 签名密钥 🔴
- **位置**：`judge-auth/.../JwkController.java`、`JwtTool.getPublicKeyBase64()`、网关白名单
- **问题**：HMAC 是对称签名，`getEncoded()` 返回的就是密钥本体；该端点在免鉴权白名单且全仓无消费方。匿名 GET 即可拿到密钥、离线伪造任意身份 token（2026-09-23 实测已复现完整绕过链）。
- **修复**：按 `CORE-IMPLEMENTATION.md` §4.4 方案 A —— 删除 Controller / 工具方法 / 白名单项 / 网关路由谓词 / `AuthClient` 的 Feign 方法（唯一"调用方"，实际无人用）；单元测试改为断言 `type` claim。

### S2. Refresh token 可直接当 Access token 用 🔴
- **位置**：`judge-gateway/.../JwtUtils.parseIdentity`（从不校验 `type` claim）、`AccountService.refresh`
- **问题**：30 天有效期的 refresh token（经 HttpOnly Cookie 流转）放进 `Authorization` 头即可全权访问 —— 被盗 cookie 的危害从"可续签"升级为"30 天完整身份"。
- **修复**：网关 `parseIdentity` 只放行 `type=access`；`/accounts/refresh` 只接受 `type=refresh`（access token 不得用来续签）。

### S3. `PUT /users` 水平越权（IDOR → 可接管管理员账号）🔴
- **位置**：`UserController.updateCurrentUser`（无 `@RequireRole`，目标取 `form.getId()`，且 `UserService.updateUser` 受理密码修改）
- **问题**：任意学员传 `{"id": <管理员id>, "password": "x"}` 即可重置管理员密码。
- **修复**：目标强制取 `UserContext.getUserId()`；新增 `UserService.updateProfile`（只放行 name/icon/email，永不触碰 password/status/type/cellPhone/username）；管理操作仍走 `@RequireRole(STAFF)` 端点。前端 `ProfileView` 无需改动（字段兼容）。

### S4. `PageQuery.sortBy` SQL 注入（布尔盲注）🔴
- **位置**：`judge-common/.../PageQuery.toMpPage` —— 客户端可控字符串原样进 ORDER BY（MyBatis-Plus `OrderItem.column` 是字符串拼接）；暴露面含 `/users/page` 等全部分页接口。
- **修复**：列名白名单正则 `^[a-zA-Z][a-zA-Z0-9_]*$`，不匹配静默回退默认排序列；顺带落实 `MAX_PAGE_SIZE` 钳制与页码下限（原常量是死代码）。

### S5. `/accounts/admin/login` 完全不受登录限流保护
- **问题**：限流谓词只有 `Path=/accounts/login`，兼容别名可绕过防爆破限流打员工账号。
- **修复**：谓词改为 `Path=/accounts/login,/accounts/admin/login`（兼容端点保留，但与统一入口同一限流水位）。

### H1. judge-ai 生成链路在 Netty 事件循环上执行阻塞 IO
- **位置**：`ReviewService` —— 每个 DELTA 的 Redis 缓冲写、END 帧的 JDBC + Embedding `block()`、`doOnCancel` 的 JDBC，全部跑在 `reactor-http-nio` 线程上
- **问题**：高并发下事件循环被阻塞 = 整服务卡死；`block()` 抛 `IllegalStateException` 被吞 → 历史点评向量索引静默失效。
- **修复**：生成链路 `publishOn(Schedulers.boundedElastic())`（切在 delta 发射之后、全部阻塞点之前）；`doOnCancel` 的落库调度到 boundedElastic。

### F1. AI 点评面板把雪花 ID 转 Number（功能坏死且静默）
- **位置**：`AiReviewPanel.vue:161,234` —— 19 位雪花 ID 被 2^53 截断 → 点评/历史查询必然 404，且历史失败被 `catch` 吞成空列表。
- **修复**：删除两处 `Number()`，字符串透传。同类残留一并清零：`ProblemDetailView`（problemId/contestId）、`ProblemEditView`、`KnowledgeView` ×3，共 9 处。
